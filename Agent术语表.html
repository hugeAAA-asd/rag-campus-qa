📚 Agent 开发常用术语表

结合 RAG + Function Calling 项目整理 · 面试速查

🧠 一、大模型基础

温度 Temperature
控制输出随机性。越高越发散，越低越确定。文档问答用 0.2~0.3，聊天可以用 0.7
Token Token
大模型处理文本的最小单位。中文大概 1 个字 ≈ 1~2 token。输入输出都算钱
上下文窗口 Context Window
模型一次能读进去的最大 token 数。超过就会"忘事"，需要裁剪历史消息
幻觉 Hallucination
大模型一本正经地编造不存在的事实。RAG 就是用来减少幻觉的核心手段
系统提示词 System Prompt
给大模型定角色和规则的那段话，优先级最高，通常放在 messages 第一条
推理 / 思维链 Reasoning / CoT
大模型先"想"再答，输出思考过程。比如 DeepSeek-R1 的 reasoning_content

🤖 二、Function Calling / Agent

函数调用 Function Calling
大模型判断需要外部数据时，返回要调用哪个函数、传什么参数，由本地代码执行后再把结果喂回模型
工具调用 Tool Call
和 Function Calling 一个意思，"工具"是更宽泛的说法（天气、时间、计算器都是工具）
工具描述 Tool Schema
告诉大模型有哪些工具、每个工具叫什么、要传什么参数的那段 JSON 定义
智能体 Agent
大模型 + 工具 + 循环 = 能自己规划步骤、调用工具完成任务的系统
链式调用 Chained / Multi-step
多步任务，模型调完一个工具，根据结果再调下一个，直到任务完成
ReAct 模式 Reason + Act
思考→行动→观察→再思考，Agent 的经典循环模式
工具选择模式 Tool Choice
auto=模型自己决定要不要调工具；required=必须调；none=不许调

🔍 三、RAG 检索增强生成

嵌入 / 向量化 Embedding
把文字变成一串数字（向量），语义相近的文字向量也相近
文本分块 Chunk
长文档切成一小段一小段，不然一次塞不进 prompt。中文一般 300~500 字一块
重叠 Overlap
相邻两块重叠一部分文字，防止答案正好卡在切口处丢失上下文
余弦相似度 Cosine Similarity
两个向量有多像，范围 -1 到 1，越接近 1 表示越相似
Top-K Top-K
检索时取相似度最高的 K 段文档，K 越大召回越全但越慢越贵
重排序 Rerank
粗检索先召回 10 条，再用更精细的模型重新排序取前 3，大幅提升准确率
召回率 Recall@K
正确答案在检索结果前 K 名里出现的比例。比如 recall@1=25/32
向量数据库 Vector Store
存所有文档向量的地方，用来快速找相似内容。轻量版可以就是一个 JSON 文件

⚙️ 四、工程化相关

API 密钥 API Key
调用大模型服务的密码，通常以 sk- 开头，要放在 .env 里不能写死在代码中
环境变量 .env
把密钥和配置和代码分开管理，代码上传 GitHub 时不会泄露密钥
提示词工程 Prompt Engineering
设计 system prompt 和用户输入格式，让大模型更好地完成任务
流式输出 Streaming
回答一个字一个字蹦出来，不用等全部生成完再显示，体验更好
延迟 Latency
从用户提问到拿到回答要等多久。本地模型首次加载慢，之后就快了

🎯 面试最常问的 5 个问题

Q1: 幻觉是什么？怎么解决？
大模型编造不存在的事实。用 RAG 让它基于真实文档回答，加 system prompt 约束"资料里没有就说不知道"。
Q2: Temperature 高了低了有什么区别？
高=有创意但容易瞎编，低=稳定但死板。文档问答用 0.2，聊天对话用 0.7。
Q3: RAG 解决什么问题？
解决大模型知识过时、不知道私有数据、容易幻觉的问题。先检索私有文档，再让模型基于文档回答。
Q4: Function Calling 流程是什么？
告诉模型有哪些工具 → 模型返回要调哪个函数+参数 → 本地执行 → 把结果喂回模型 → 模型总结回答。
Q5: Chunk Size 怎么选？
太大检索噪音多，太小上下文不完整。中文一般 300~500 字，overlap 设 10~20%。
